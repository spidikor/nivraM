# Property response binding

The local property panel now requests `nivram-properties/1` responses using a fresh 32-hex request ID. The server returns `schema`, `requestId`, `sourceGraph`, `sourceIdentity`, and the unchanged `properties` report. `sourceGraph` is the original parsed request, not a regenerated molecule. `sourceIdentity` is independently obtained from that original snapshot before calling the property producer. A disagreement between this identity and the report is rejected before transmission. Legacy API callers that omit `requestId` continue receiving the original top-level report, with the same server validation.

The browser requires its requested envelope, exact request ID, exact JSON graph data, identity agreement, and current document revision. It does not fall back to an unbound report. Object key order is immaterial; array order, atom IDs, coordinates, annotations, and omitted versus explicit defaults remain significant. The comparison UI requests `sourceBinding: "nivram-source/1"`; both sides return their own original source graph and independently derived identity. Legacy comparison callers remain supported without that opt-in. Modern comparison callers reject unbound or mismatched replies.

Existing Python graph hashes and persisted report formats are unchanged. Python JSON serialization is not JavaScript JSON serialization, including number spelling and Unicode escaping. The browser checks hash syntax and agreement with the server's separately derived identity; it does not attempt to recreate Python's graph digest. Python preparation admission retains exact graph-hash and UTF-8 SMILES-hash recomputation. Standalone `document.prepareRender` performs report-schema and scene consistency checks, but without an authoritative source identity its graphHash remains syntax-only/opaque. It does not independently bind that digest to its graph. Analysis and modern comparison have the additional source envelope; comparison preview identities are checked against the bound side.

Data-only validators enforce complete report keys, fixed units and descriptor labels/methods, finite values, paired mass availability, status/value agreement, and source-derived formal charge and connected-component count. Any explicitly charged source atom requires the charged LogP warning, including net-zero zwitterions. The same warning is also permitted for native charge separation from an uncharged source, such as neutral nitro sanitization; source-charge absence alone cannot rule that out. Missing isotope-mass claims must reference unique explicit source labels. Source-derived domain exclusions and exact warning order remain consistent with the producer. Radical warnings match source annotations: the existing native graph conversion rejects a radical count that differs from the submitted count. Present scene reports are checked against graph and displayed formula, SMILES and rounded mass before adoption. Empty rendered scenes retain their historical mass of zero while their descriptor masses remain null.

## What this establishes

The bound analysis/comparison paths detect malformed, inconsistent and stale reports, including a changed identity field that disagrees with the authoritative envelope. Standalone scene admission has the hash-verification limitation described above. They preserve the existing cancellation, revision, preview-isolation and trusted local-engine boundaries. They do not authenticate a response with a cryptographic signature or independently verify formula, molar mass, exact mass, LogP, or the engine isotope table. A fully coherent fabricated report can still pass transport validation, including a fabricated but mutually consistent native charge-separation or nonfinite-engine warning. In particular, internally consistent finite values of 999 and a well-formed false C13 missing-table claim are deliberate trust-limit regression controls, not scientifically accepted results.

No alternate mass table, chemistry engine, inference provider, normalization or stored-hash migration is introduced. Renderer/font and Windows runtime acceptance remain separate checks. Tests with controlled scenes or unavailable previews do not prove successful rendering.

## Local cost observation

Thirty warmed sequential samples on the existing Python/RDKit runtime gave these medians (milliseconds): empty graph calculation 0.030, independent identity 0.018, complete bound response 0.095; ethanol 0.234, 0.099, 0.530; a 512-carbon chain 24.861, 14.618, 42.007. The complete response includes snapshot copies, independent native identity reconstruction and schema checks. These are local observations, not latency guarantees, cross-machine benchmarks or independent chemical validation. The graph atom/bond limits remain unchanged.
