# Conservative stereo after deletion

Deleting a single bond beside a defined E/Z double bond used to leave a stereo
reference atom present but disconnected from its required endpoint. Native
validation then rejected the edit. Clearing that reference alone was insufficient:
imported SMILES direction flags could reconstruct a new E/Z assignment using a
surviving alternative ligand. Clearing a shared directional edge could instead
remove a valid neighboring configuration.

## Accepted edits

The shared deletion command clears a double bond's stereo and references when a
reference atom or its connecting edge is removed. Reference order corresponds to
the double bond's begin and end atoms. Reversed edges are supported. It does not
choose a replacement reference, change unrelated atom fields, or turn an empty
deletion into a repair operation. Existing atom-chirality invalidation policy is
unchanged.

Native validation now treats the graph's explicit double-bond annotations as the
authority. Imported slash/backslash direction flags are removed before native
cleanup; surviving graph-defined configurations are restored only on currently
stereogenic double bonds. Native directions are regenerated from those accepted
annotations for serialization. Wedge, dash and explicit unknown annotations retain
their separate handling. Geometry checks continue to reject contradictory E/Z
coordinates. No coordinates are regenerated by validation or export.

Actual-import regressions include:

- `C/C=C(/C)Cl`: deleting the chlorine reference gives unspecified `CC=CC.Cl`.
- `C/C=C(Cl)/C=C/C` and its neighboring Z variant: deleting the chlorine edge
  clears the affected double while preserving the neighboring E/Z configuration.
- Atom deletion, reversed endpoints, disconnected stereo components, tetrahedral
  centers, explicit hydrogens, isotopes, charge, atom maps and coordinate fidelity.

## Conservative refusal when serialization is lossy

The pinned RDKit 2025.09.4 writer cannot safely serialize every partially specified
conjugated chain. For example, deleting chlorine from `C/C=C/C(Cl)=C/C=C/C`
leaves an unspecified middle double between two defined doubles. The writer emits
SMILES with all three defined, including when the middle is marked explicitly
unknown. That edit is rejected, retaining the previous drawing; neither outer
configuration is discarded to make the edit succeed.

The check compares the native double-bond annotations with the reparsed actual
SMILES output, using the writer's atom-output order and reference-normalized
cis/trans parity. It does not compare two canonical SMILES strings, which could
hide the same lossy conversion twice. User atom maps are not rewritten. Plain
SMILES does not distinguish omitted stereo from an explicit unknown marker; both
must remain without a defined configuration. The graph and MOL retain their
separate unknown annotations.

MOL export removes SMILES-only direction flags on a private molecule copy, allowing
undefined double bonds to receive the native CFG=2 marker. Round-trip identity is
checked, and the submitted graph remains unchanged.

## Offline verification

With the existing Node and project RDKit runtimes, from the source directory:

```
node --test tests/stereo-delete.test.mjs tests/edit-commands.test.mjs tests/bond-edit.test.mjs tests/document.test.mjs
PYTHONDONTWRITEBYTECODE=1 python -m unittest tests.test_stereo_delete tests.test_chemistry tests.test_mol_stereo_roundtrip tests.test_stereo_inspector tests.test_reflection tests.test_reflection_meso tests.test_rotation tests.test_atom_hydrogen_radicals tests.test_smiles_hydrogen_preservation tests.test_properties -v
```

These are synthetic structural regression checks, not experimental chemistry
validation or a full release qualification. The earlier failing candidate and
its counterexamples remain preserved in the private checkpoint history.

Browser interaction, native Windows GUI, actual rendering and font qualification
remain separate checks. Pointer, keyboard and image-correction callers use the
same deletion helper, but these offline checks do not qualify their complete
user-interface flows. No dependencies were installed or upgraded for this change.
