# MOL atom annotation support boundary

The editable 2D graph cannot preserve MOL atom aliases (`molFileAlias`), atom values (`molFileValue`), or attachment-point declarations (`molAttchpt`). Import now rejects nonempty alias/value text and nonzero attachment declarations rather than returning an apparently successful flattened drawing. This intentionally narrows acceptance of previously accepted annotated inputs. Resolve the annotation explicitly in the source editor or remove it from a copy before importing. The importer does not infer or expand an alias.

The shared molecule-to-graph gate covers direct conversion and ordinary MOL import. Protected import and batch preparation expose the fixed `unsupported_atom_annotation` error; batch failure remains per-file. Text MOL metadata in PNG reports an unsupported source with no graph. Optical import preserves its existing `unsupported_abbreviation` error for aliases, including aliases on ordinary atoms. Other optical annotation failures retain the existing unsupported-chemistry error wrapper.

Finite parser-backed fixtures establish V2000 A alias records, V value records, M APO records and genuine V3000 ATTCHPT declarations. Empty alias/value strings carry no text and remain accepted. Nonempty whitespace is not trimmed. V2000 APO=0 and V3000 ATTCHPT=0 parse as absence; direct integer-zero attachment properties are likewise defaults. Other retained attachment values are rejected, without adding a new allowed-value domain. The V3000 writer drops alias/value properties and is not used to pretend those annotations were present in source.

No blanket private-property rejection, new MOL parser, graph schema, annotation renderer or automatic chemistry expansion is introduced. Supported charge, isotope, radicals, map numbers, explicit hydrogen information, stereo and coordinates retain their existing contracts. This is not an exhaustive audit of every MOL annotation or parser discard.

Validation uses source-property assertions before exercising the boundary, genuine text fixtures, positive chemistry/coordinate controls, controlled batch and worker seams, and the actual JavaScript transaction function with controlled adapters. These seams do not establish native Windows UI or Job Object success. Linux protected import remains unavailable by design, and real rendering requires Arial. No resource-limit bypass or font substitution is part of this repair.
